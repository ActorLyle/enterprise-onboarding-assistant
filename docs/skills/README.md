# 入职助手 Skills 配置说明

本目录包含 6 个可直接导入或复制到“Plan + Skill 可配置执行平台”的 Skill 配置文档：

1. `01_入职问题结构化_Skill.md`
2. `02_入职任务决策_Skill.md`
3. `03_入职流程解释_Skill.md`
4. `04_制度与知识问答_Skill.md`
5. `05_入职沟通话术生成_Skill.md`
6. `06_合规与风险审核_Skill.md`

## 统一知识库策略

平台只配置一个逻辑知识库：`入职知识库`。

系统不对前台用户区分“主检索”或“追问后检索”。实际执行时，由检索层自动使用用户问题和上下文中可获得的条件，例如：

- 城市；
- 岗位类别；
- 人员类型；
- 系统名称；
- 入职日期；
- 故障现象。

这些条件用于提高召回与排序精度，但不形成两条对用户可见的业务链路。

## 推荐执行链路

```text
用户问题
  ↓
入职问题结构化 Skill
  ↓
统一入职知识库检索
  ↓
入职任务决策 Skill
  ↓
入职流程解释 Skill / 制度与知识问答 Skill
  ↓
入职沟通话术生成 Skill
  ↓
合规与风险审核 Skill
  ↓
最终回复
```

## 调用原则

- “入职流程解释”与“制度与知识问答”可根据问题类型二选一，也可以串行组合。
- “合规与风险审核”必须是最终节点。
- 任一检索为空时，必须明确返回“当前系统未查询到相关信息”，不得由模型补充。
- 当前知识库仅覆盖入职相关场景，不能替代 HR、IT、直属上级对个人状态、审批、薪酬、合同和权限的最终确认。

## 关键实现建议

1. 每个 Skill 的 Prompt 存在 `skills.json` 中，支持后台修改与启停。
2. 统一知识库检索结果以 `knowledge_cards` 形式传递给后续 Skill。
3. 后续 Skill 只允许引用输入中的 `knowledge_cards` 或上游结构化结果。
4. 将 `evidence_summary` 写入执行日志，便于风控追溯。
5. 风控不通过时，使用 `safe_reply` 覆盖原始草稿，不得直接回传原文。
