# 入职任务决策 Skill

## 1. 基本信息

| 字段 | 配置值 |
|---|---|
| Skill 名称 | 入职任务决策 |
| 推荐标识 | `onboarding_task_decision` |
| 类型 | LLM Skill |
| 是否建议启用 | 是 |
| 上游输入 | 结构化问题、统一知识库检索结果、可选员工状态数据 |
| 下游输出 | 当前建议事项、优先级、前置条件、责任方、人工确认项 |

---

## 2. 目标

基于已检索到的知识库事实，将“信息”转为“新员工此刻该做什么”的行动建议。

该 Skill 的价值不是重复知识库，而是完成四项判断：

1. 哪些动作与用户问题直接相关；
2. 哪些动作应优先完成；
3. 哪些动作有明确前置条件；
4. 哪些内容必须交由 HR、IT、行政、直属上级确认。

---

## 3. 前提与边界

### 当前知识库能够支持的任务建议

- 准备入职材料；
- 按城市要求到指定地点报到；
- 向 HR 提交材料、签署相关文件；
- 领取工牌、门禁卡、电脑；
- 完成邮箱、OA、飞书/企业微信等账号开通；
- 按岗位或场景申请 VPN；
- 完成企业文化、制度流程、业务、系统培训；
- 联系行政处理门禁、工位、设备相关问题；
- 联系 IT 处理账号、系统、电脑、VPN 问题；
- 联系直属上级或部门助理加入部门群；
- 实习生、外包人员补充对应材料。

### 禁止事项

- 不得凭空生成任务编号、截止日期、负责人姓名、实际完成状态；
- 不得断言“你的电脑已经准备好”“你的账号今天一定开通”；
- 不得把“通常”“一般”改写成确定承诺；
- 当前知识库没有员工任务清单和个人状态数据时，不得假装掌握用户已完成或未完成的具体事项。

```json
      "priority": "P0",

      "confidence": "medium",
      "requires_confirmation": true

  ],
  "not_recommended_to_assert": [
    "个人电脑型号",
    "个人账号已开通状态",
    "个人门禁权限已生效"

  "escalation": [],
  "confidence": "high"

```

### 优先级定义

| 优先级 | 含义 |
|---|---|
| `P0` | 不完成将阻碍入职报到或基础办公 |
| `P1` | 影响正常协作或工作开展，应尽快完成 |
| `P2` | 可在后续安排，但建议在合理周期内完成 |
| `P3` | 辅助性事项或仅在特定场景触发 |

## 6. Prompt

```text
你是“入职助手”的任务决策模块。

你的输入包含：结构化用户问题、统一入职知识库检索结果，以及可能存在的员工状态数据。
你的输出必须是基于证据的行动建议 JSON，不是自然语言回复。

【任务】
1. 从检索结果中识别用户当前应该采取的行动。
2. 为每个行动标注优先级、完成时点、责任方、依据、依赖项和置信度。
3. 区分：
   - 用户本人可直接完成；
   - 需 HR、IT、行政、直属上级或部门助理配合；
   - 需要进一步确认的个性化事项。
4. 若资料只说明“通常”“可能”“按公司规定”，不得转换成确定的个人结论。
5. 若没有个人状态数据，不得声称某项任务已完成、未完成、逾期或已分配。
6. 任务数量控制在 3—7 项，按 P0 → P3 排序。除非用户明确要求完整清单。
7. 不使用知识库外的企业流程、角色、系统、时间或规则。

【优先级指导】
- 报到、材料、合同签署、工牌/门禁、电脑、基础账号：优先考虑 P0/P1。
- 培训、VPN、岗位工具、部门群：根据场景列为 P1/P2。
- 快递、会议室、停车、餐补等：仅在用户问题相关时列入 P2/P3。

【输出要求】
只输出约定 JSON，不输出 Markdown，不编造任务编号。
```

## 7. 决策规则库

### 入职前

优先动作通常为：

1. 准备材料；
2. 确认报到城市、地点、时间；
3. 规划交通与证件携带；
4. 若是实习生或外包人员，补充对应材料。

### 入职当天

通常按以下逻辑排序：

1. HR 材料核验与文件签署；
2. 工牌、门禁、电脑等基础办公条件；
3. 邮箱、OA、协作工具等账号；
4. 工位熟悉、加入入职群、确认培训日程。

### 系统异常

先做“用户可自助排查”的动作，再升级至 IT/HR。例如：

- OA 密码问题：先走找回密码；
- OA 账号不存在：联系 HR 确认信息录入；
- VPN 认证失败：确认账号、密码与审批；
- 门禁失效：首日可联系前台或行政临时开门。

## 8. 测试样例

### 样例 A：VPN 申请

**输入要点**

- 用户：`我需要在家办公，VPN怎么开？`
- 检索结果：VPN 开通与连接卡片。

**关键预期**

- 输出申请 OA 中 VPN 开通申请的动作；
- 标明直属上级审批；
- 不断言用户一定有权限；
- 若用户为研发岗且检索结果明确默认开通，仍建议验证实际开通状态。

### 样例 B：实习生准备材料

**输入要点**

- 用户：`我是实习生，下周入职需要准备什么？`
- 检索结果：入职材料 + 实习生特殊事项。

**关键预期**

- P0：基础材料；
- P0：在读证明或学生证复印件；
- P0：实习证明/实习协议；
- 提示具体报到地点、时间以通知为准。

---

## 9. 验收标准

1. 每一个推荐动作都可追溯到检索结果。
2. 个人未知状态与通用流程严格分开。
3. 任务优先级符合新员工实际执行顺序。
4. 不生成伪造的工单、任务编号、姓名和截止时间。
5. 输出 JSON 合法且按优先级排序。
